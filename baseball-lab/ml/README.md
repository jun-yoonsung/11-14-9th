# 예측 모델 정리 (앞으로 5년 성적·현역 확률)

결과 화면의 "앞으로 5년 예측"을 만드는 모델의 데이터, 방법, 정확도, 한계를 한곳에 정리한 문서입니다.

## 1. 무엇을 예측하나
| 대상 | 예측값 | 시점 |
|---|---|---|
| 타자 | OPS(출루율+장타율) | 1~5년 뒤 |
| 투수 | ERA(평균자책점) | 1~5년 뒤 |
| 타자·투수 | 그 해에도 KBO 1군 기록이 남아 있을 확률(현역 확률) | 1~5년 뒤 |

- 은퇴 예상 나이는 현역 확률이 50% 아래로 처음 내려가는 나이입니다. 5년 안에 내려가지 않으면 "5년 안에는 높게 유지"로 표시합니다.
- 현역 확률은 부상, 군 복무, 해외 진출도 "기록 없음"으로 잡습니다. 은퇴의 정확한 연도를 맞히는 모델이 아닙니다.
- 성적 예측은 "그 해에 충분히 뛴다(타자 100타석, 투수 30이닝 이상)"는 가정의 값입니다.

## 2. 데이터
- Kaggle **KBO Player Stats 1982–2026** (작성자 netsong, KBO 공식 기록 기반, **CC BY-NC-SA 4.0**).
- 선수 한 명의 한 시즌이 한 행입니다(타자 10,209행, 투수 7,971행). 나이(`Age`), 생년월일(`Born`)과 KBO 선수 번호(`Id`)가 있습니다.
- 우리 사이트의 `pid`와 같은 번호입니다(2026 투수 296명 전원 일치, 자책점·삼진 값 일치 확인).
- **원본 CSV는 재배포 금지 라이선스라 GitHub에 올리지 않습니다**(`ml/raw/`는 `.gitignore`). 예측 결과와 출처 표기만 공개합니다. 비영리 수업 프로젝트에서만 사용합니다.
- KBO 공식 사이트(koreabaseball.com)는 `robots.txt`가 검색 엔진 외 자동 수집을 금지하므로 직접 수집하지 않았습니다.

## 3. 방법
1. 선수-기준시즌마다 최근 3시즌 기록, 나이, 경력, 리그 평균을 특성으로 만들고, t+1~t+5 시즌 기록을 정답으로 붙입니다(`train_forecast.py`).
2. 1990 시즌 이후 자료만 학습에 씁니다. 시점(1~5년 뒤)마다 모델을 따로 학습합니다.
3. **시간 순서 검증**: 학습(예측 대상 ~2020) → 구간 폭 보정과 모델 선택(2021~2023) → 시험(2024~2026). 시험 구간은 학습·보정·선택에 쓰지 않습니다.
4. 비교 기준선 3가지: 작년 값, 최근 3시즌 가중평균(Marcel식), 리그 평균. 시점마다 검증 구간에서 가장 나은 방법을 자동으로 고릅니다.
5. 80% 예측 범위는 분위수 회귀로 만들고, 검증 구간에서 실제로 80%가 들어오도록 폭을 보정합니다.

## 4. 모델 비교와 선택
`compare_models.py`(성적), `compare_classifiers.py`(현역 확률). 결과는 `model_comparison.json`.

| 대상 | 비교한 후보 | 선택(검증 구간 기준) |
|---|---|---|
| 타자 OPS | Ridge, 랜덤포레스트, ExtraTrees, 부스팅 3종, 앙상블 | ExtraTrees + 랜덤포레스트 + 부스팅 2종의 **평균** |
| 투수 ERA | 같은 후보 | MAE 손실 **부스팅** 단독 |
| 현역 확률 | 로지스틱, 랜덤포레스트, ExtraTrees, 부스팅 2종 | 부스팅(투수는 랜덤포레스트와 오차 범위 안) |

## 5. 정확도 (시험 구간 2024~2026, 평균 오차 / 낮을수록 좋음)
| | 1년 뒤 | 3년 뒤 | 5년 뒤 |
|---|---|---|---|
| 타자 OPS(선택된 방법) | 0.071 | 0.075 | 0.071 |
| 타자 OPS(작년 기록 그대로) | 0.092 | 0.097 | 0.109 |
| 투수 ERA(선택된 방법) | 1.106 | 1.203 | 1.067 |
| 투수 ERA(작년 기록 그대로) | 1.445 | 1.567 | 1.641 |

- 80% 범위에 실제 값이 들어온 비율은 74~92%입니다.
- 현역 지속 구분력(AUC)은 0.79~0.84입니다.
- 최신 수치는 `metrics.json`과 화면의 "이 예측은 얼마나 믿을 수 있나요?"에서 확인합니다.

## 6. 한계 (솔직한 정리)
- **"제일 정확한 모델"이라고 보장하지 않습니다.** 후보 중 검증 구간 기준 최선이며, 타자는 트리 계열 모델끼리 차이가 사실상 없었습니다.
- 투수 시험 구간 표본이 146~282개로 작아서 모델 사이의 작은 차이는 우연일 수 있습니다. 실제로 투수 시험 구간에서는 ExtraTrees(1.106)가 선택된 모델(1.136)보다 나았지만(둘 다 1~5년 평균), 시험 결과를 보고 모델을 바꾸지 않았습니다.
- 투수 3년 뒤(1.203)는 리그 평균(1.176)보다 약간 나쁩니다. 검증 구간에서는 모델이 더 나았기 때문에 그대로 두었습니다.
- XGBoost, LightGBM, 신경망, 선수별 시계열 모델은 비교하지 않았습니다.
- 특성이 기록·나이·경력 위주입니다. 부상, 군 복무, 구속 변화, 타구 질은 반영하지 못합니다.
- 먼 미래일수록 불확실성이 큽니다. 한 시즌 값이 아니라 80% 범위를 함께 봐야 합니다.
- 성적 예측은 "그 해에 뛴 선수"만 대상으로 학습해, 뛰지 못하는 경우의 성적은 말하지 않습니다.

## 7. 다시 학습하는 방법
1. Kaggle에서 CSV 2개를 받아 `ml/raw/`에 둡니다(`kbo_batting_stats_season_1982-2026.csv`, `kbo_pitching_stats_season_1982-2026.csv`).
2. `python3 ml/train_forecast.py` → `public/data/forecast.json`, `ml/metrics.json` 갱신.
3. 모델을 다시 비교하려면 `python3 ml/compare_models.py`, `python3 ml/compare_classifiers.py`.
4. 필요한 패키지: pandas, numpy, scikit-learn.

# AI 해설 (참고)
- 사이트에서 LLM을 부르지 않고, `tools/gen_commentary.mjs`로 미리 생성해 `public/data/commentary.json`에 저장합니다(키 노출·비용·대기·문장 변동 방지).
- LLM에는 계산된 수치만 주고, 결과 문장의 숫자가 그 수치에 없으면 버리고 다시 만듭니다(최대 3회).
- 생성 대상: 타석 100 이상 타자, 90이닝 이상 투수. 사용자가 고른 지표별 해설이 아니라 선수 전체 프로필 기준입니다.
- 키는 `tools/.env`에 넣으며 GitHub에 올라가지 않습니다.
